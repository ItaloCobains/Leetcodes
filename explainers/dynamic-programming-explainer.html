Algorithms · Dynamic programming

Solve it
once. Reuse.

Dynamic programming is a table of answers to smaller questions. Each is one cell. Fill it from cells you already know. The last cell is the problem you were asked.

Dotted words open a short definition.

The one rule

If the same subproblem shows up twice, compute it once and store it. The table is the cache.

The recurrence says how a cell uses earlier cells. The fill order must visit those earlier cells first.

01 · State. One cell, one question. Example: ways(i) = how many ways to climb i steps using 1 or 2.

02 · Recurrence. ways(i) = ways(i-1) + ways(i-2). Two smaller answers make this one.

03 · Order. Fill i = 0, 1, 2, … so the two lookups already exist.

01

The same call happens again

A recursive function that asks ways(n-1) and ways(n-2) is correct. It is also exponential, because those two branches ask many of the same smaller values.

  • Overlap. ways(4) needs ways(3) and ways(2). ways(3) also needs ways(2). The second ways(2) is not new work.
  • A tree, not a line. Each call splits in two. The number of leaves grows like Fibonacci itself.
  • The table collapses the tree. After the first ways(2), every later request is a lookup.
02

Three ways to get the same number

The running example is stairs: n = 5, steps of size 1 or 2. The answer is 8. and a store each cell once. Recursion does not.

        Optimal substructure
        
A best answer is made of best answers to smaller states. If that is false, a table of best-so-far is the wrong tool.

        
Stairs has it: every way to reach i ends with a 1-step from i-1 or a 2-step from i-2.
